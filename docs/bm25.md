# BM25 baseline

Search a verified parsed dataset without contacting PubMed:

```sh
python -m pip install -e '.[retrieval]'
python scripts/bm25_search.py data/parsed/depression-cbt \
  --query 'cognitive behavioral therapy depression' \
  --top-k 10 --output results/bm25/depression-cbt.json
```

The CLI prints JSON and optionally saves it to a new file. Existing output files
are never overwritten. Dataset checksums and provenance are verified before
indexing. The index is rebuilt in memory on each invocation; candidate pools are
small, and no persistent index or global document cache is needed yet.

## Search policy

Each article is one document: title followed by the primary abstract's section
text in source order. Both fields appear once, without extra title weighting.
Section headings, metadata, other-language abstracts, and book titles are excluded.
Missing abstracts leave title-only documents. Empty documents remain in corpus
statistics; an empty dataset or vocabulary returns no hits.

Documents and queries use NFC Unicode normalization, case folding, whitespace
normalization, and the Unicode word pattern `(?u)\b\w+\b`. Single letters, numbers,
abbreviation components, and negations survive. Punctuation splits words: `CBT-I`
becomes `cbt`, `i`. There is no stemming, stopword removal, expansion, phrase
matching, or Boolean query syntax. `AND` is an ordinary term. Preserving `not`
does not mean BM25 understands negation.

BM25S 0.3.14 uses its Lucene variant with `k1=1.5`, `b=0.75`, NumPy, and float64
scores. These are starting parameters, not tuned values. Change them with `--k1`
and `--b`. For a term appearing in `df` of `N` candidates:

```text
idf = log(1 + (N - df + 0.5) / (df + 0.5))
term_score = idf * tf / (tf + k1 * (1 - b + b * document_length / average_length))
```

Scores sum over query tokens; repeated query tokens contribute repeatedly.
BM25S omits the constant `k1 + 1` factor used by some formulations. This does not
change ranking at fixed parameters. Scores depend on this candidate set and are
not probabilities or comparable across datasets. Unknown terms contribute zero.
Zero-score documents are omitted, so fewer than `top-k` hits is valid. Equal scores
retain the original PubMed candidate order.

## Run output

A report includes the original and normalized query, query tokens, full search
configuration, package versions, implementation hash, dataset ID, article-file
hash, candidate/token counts, timings, and ranked PMIDs with scores, titles,
PubMed URLs, and text-version IDs. Its run ID hashes the configuration and inputs;
timings are excluded. Identical run IDs identify the same experiment specification,
not byte-identical reports. Keep reports in ignored `results/`.

The saved source snapshot retains the original PubMed search and ordering. BM25
only reranks those candidates. A more specific local query cannot recover papers
missing from that snapshot.

## Saved-sample check

On 2026-10-21, the Day 3 dataset supplied 30 documents and 7,797 tokens, with no
empty documents. Index construction took about 8.5 ms and one top-10 search about
0.15 ms on the M3 Pro. These are single observations excluding imports, dataset
loading/verification, and JSON output; they are not end-to-end latency benchmarks.

The query `cognitive behavioral therapy depression` returned 10 hits. Its first
three PMIDs were `38724122`, `35061137`, and `33973857`. Two additional topical
queries returned different orders; an absent-token query returned no hits.
The [run report](experiments/bm25-baseline.json) contains identifiers, scores,
configuration, and timings without source article text.

Nine new offline tests cover independently calculated scores, length penalties,
tokenization, field selection, empty inputs, ties, repeated terms, run identity,
and the CLI with checksum failure and overwrite protection. All 55 project tests
passed. Relevance quality and nDCG@10 remain unmeasured until manual judgments
are available.
